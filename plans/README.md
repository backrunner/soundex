## Dependency Notes

- Plans 001, 002, and 003 can start independently.
- Plan 004 depends on 001 because the exported tensor shape and metadata must
  describe the final stateless model contract.
- Plan 005 depends on the corrected model, stream, data manifests, and export
  path so validation measures the deployed system rather than a Python-only
  surrogate.
- Plan 006 comes last because performance optimization must use the real
  architecture and must retain the quality gates established by plan 005.
- Do not train release weights before plans 001 through 005 are complete. Those
  plans change the model contract, data split, objective, and model-selection
  metric, so an earlier checkpoint would not be release-compatible.

## Findings Considered And Rejected

- Add a second `tract` inference backend now: rejected. ONNX Runtime already
  satisfies the requested portable artifact path; a second backend would expand
  the test matrix before the model contract is stable.
- Keep one million parameters as a minimum: rejected. A lower bound does not
  protect quality. Release gates should enforce maximum artifact size, measured
  quality, and measured latency.
- Use PESQ or FAD as the primary release metric: rejected. PESQ is speech-specific
  and FAD is a distribution metric; neither directly proves paired music
  high-band restoration. They may be secondary metrics on suitable subsets.
- Treat the passing identity ONNX tests as export validation: rejected. The
  identity graph does not exercise generator operators, model cost, phase output,
  or checkpoint compatibility.
